# Production deployment — PHP 8.4 / MySQL 8 / Nginx

1. **Server:** supported PHP 8.4 with `pdo_mysql`, `sodium`, `fileinfo`, `gd`, `mbstring`, `openssl`, `opcache`; MySQL 8; ClamAV with a working UNIX socket; php-fpm; Nginx; Redis optional. Restrict MySQL and queue backends to private interfaces. Run PHP-FPM and CLI workers as a least-privileged site user, not root.
2. **Filesystem:** deploy code to an immutable/versioned release directory. Make `app/` changes deliberate and version-controlled. Keep `storage/`, `.env`, signing keys and backups outside `public/`. Restrict secrets to the site user (`chmod 600 .env`), prevent public downloads and enable log rotation. Do not make core writable by the web process. Persist private storage across releases.
3. **HTTPS and proxies:** merge `deploy/nginx.production.conf.example` into the managed Nginx vhost, install a trusted certificate, and enable Full (strict) Cloudflare TLS if applicable. Set `APP_URL` to HTTPS, `SESSION_SECURE=true`, explicit `TRUSTED_HOSTS`. Confirm forwarded scheme handling; do not blindly trust client-supplied forwarded headers. Redact invite/reset/verify token paths at edge, origin, and log analytics.
4. **Environment:** `cp .env.example .env`, then `php bin/console setup:key`. Store APP_KEY securely; changing it breaks encrypted credentials and queued mail. Set `APP_ENV=production`, `APP_DEBUG=false`, `TENANCY_MODE=single|multi`, control host when multi, `SESSION_REGISTRY_ENABLED=true`, SMTP if mail features are enabled, and `MEDIA_SCAN_REQUIRED=true` with `MEDIA_SCAN_DRIVER=clamav`. Rotate DB/SMTP secrets using your secret manager.
5. **Database:** create a dedicated least-privilege MySQL account. Back up schema and data; rehearse restore. Run reviewed additive migrations before taking traffic, and coordinate worker drains. Migrations can alter data and are not automatically reversed by module file rollback.
6. **Smoke tests:** execute `php bin/console module:validate`, `compat:check`, `migrate:status`, `doctor`, `production:check --json`, `php tests/run.php`, `php tests/security.php`, `php tests/production.php`. In isolated CI, run `bash scripts/ci-verify.sh` against disposable MySQL schemas (never production databases), and run Chromium E2E. Verify real SMTP, virus scanning, uploads, tenant isolation, MFA, session revocation and backup restoration. Do not confuse PHP built-in load-smoke with PHP-FPM capacity testing.
7. **Release:** drain requests and jobs externally, deploy verified release artifact and retained private files, migrate, rebuild assets, clear cache and reload php-fpm. Re-enable traffic only after probes. Keep the previous deployable release for code rollback; database recovery requires a separate verified restore/forward migration plan.
8. **Supervision:** configure Supervisor/systemd for `php bin/console queue:work --max=100` in a restart loop and schedule `php bin/console schedule:run` once per minute using absolute CLI paths, with process locking and alerting. Verify failed jobs, lease expiry, worker heartbeats, queue delay, disk storage and MySQL connectivity. Ensure worker tenant context is reset between jobs.
9. **Performance:** configure PHP OPcache, Nginx compression and static immutable asset caching; observe p95/p99 latencies under representative PHP-FPM concurrency before tuning. Do not cache authenticated, tenant, invitation, or API responses at CDN layer.
10. **Operational security:** keep all maintenance toggles false outside a change window; configure firewalls, rate limiting, least privilege, security updates, backups, incident response, and monitoring. Independently review every third-party module's PHP.

**Deployment is blocked if `production:check` reports any issue**; it is necessary but insufficient evidence of production readiness. All domain, TLS, MySQL, mail, media, and worker checks must be measured on the actual infrastructure.
